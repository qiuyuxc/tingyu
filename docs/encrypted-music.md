# 加密音乐

支持读取和播放 ChunkSeal V1/V2（`.cseal`，文件头 `CSEA`）与旧 NCMX V1（`.ncmx`）。
容器中的音频保持原始编码，解密后的数据交给现有播放器；Android 8.1 及以上继续使用
Media3 的浮点音频配置与 FLAC 解码路径。

## 使用

在“我的 → 设置 → 音乐与文件 → 加密与密钥”展开“高级”，
使用“导入密钥或旧口令”导入加密文件时使用的凭据。
随机密钥是完整的 `cseal2:` 导出，支持 16 或 32 字节主密钥。
口令保留原始文本，包括空格与换行。导入新凭据、重新生成当前密钥都会保留已有凭据。
此页面及密钥环复用听屿现有实现，提供复制当前密钥、复制旧凭据与高级折叠。
完整的 `cseal2:` 导出只作为随机密钥；普通文本作为口令，读取时按文件声明的模式选择候选。
升级会迁移 0.12.10 已导入的凭据；上一版明确导入的空口令及带标记的文本口令仍按原类型读取。

本地目录中的加密文件参与音乐扫描；没有对应凭据时仍保留在曲库并显示读取提示。
导入凭据后重新打开曲库或扫描目录，可以读取歌名、艺人、专辑、歌词、封面和时长。
云端文件菜单提供播放入口，HTTP、S3 和 OpenList 使用相同的读取规则。

不同包名的应用分别保存密钥。由另一份应用加密的文件，需要从那份应用复制对应密钥，
或输入原口令。重新生成密钥不改变已有文件，旧凭据继续用于读取。

## 代码

- `Ncmx.kt`：从听屿已有格式层整理出的读取部分，包含头部检查、密钥派生、认证、
  元数据与随机音频读取。新旧格式都按原文件头认证，认证失败不会改走其他格式。
- `SettingsPage.kt`：现有「加密与密钥」页面、折叠、复制及导入弹窗。
- `CloudKeyRing.kt`、`Cloud.kt`、`ChunkSealKeys.kt`：原有密钥环、编号候选顺序、无损保存与随机密钥解码。
- `ImportedMusicKeys.kt`：兼容 0.12.10 的旧导入格式；新的凭据通过原密钥环保存。
- `EncryptedMusic.kt`：共用密钥环的本地文件与云端来源、音乐标签读取。
- `EncryptedReader.kt`：认证后交付数据，最近使用的明文块最多缓存 8 MiB。
- `MusicDataSource.kt`、`BorrowedMediaDataSource.kt`：播放器适配与数据源生命周期。
  Media3 拖动时可以关闭并重开读取，底层文件由 Player 在切歌、停止和失败后释放。

云端读取使用 HTTP Range，起播与拖动均无需下载整个容器。
取消读取会断开当前数据源持有的网络连接；网络读取期间不持有缓存锁。
元数据中的 `gainDb` 沿用现有只减不增的响度处理。

ChunkSeal 的来源为 [kity-yolo/chunkseal-protocol](https://github.com/kity-yolo/chunkseal-protocol)，
按听屿的 [GPLv3 集成授权](../licenses/ChunkSeal-GPL-Permission.md) 集成。
协议正文、版权与授权副本都保留在应用关于页。

## 回归

0.12.11 按维护者要求直接编译出包，未重新运行回归测试、Lint、播放诊断或设备界面检查。
以下为已有测试的覆盖范围，0.12.10 的执行结果保存在对应版本验证记录中。

`EncryptedKnownAnswerTest` 使用协议仓库的七组固定向量和独立 Python 生成的旧 NCMX 向量，
核对完整音频与元数据。其余读取测试覆盖跨块拖动、短尾块、EOF、错误密钥、损坏块、
截断文件、类型隔离、源释放与正在读取时关闭。
`EncryptedStorageTest` 通过本机 HTTP 服务验证三种后端的列表与按块播放，
并验证打开操作结束后可以继续读取、关闭播放源会取消网络请求。

这些检查验证容器与读取链路；设备上的解码、声音和界面操作按实际验收记录说明。

在 Android 主机上可使用 `android/tools/run-encrypted-playback-smoke.py` 加载正式 APK，
核对实际加密 FLAC 的完整音频摘要、格式识别，以及 Media3 读取器关闭后的重新打开与拖动。
脚本通过 `--android-jar` 指定 SDK，口令从单独的 UTF-8 文件读取，摘要使用独立参照值。
该检查不创建应用窗口，也不输出声音。
